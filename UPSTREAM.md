# Upstream

chokibare is a translation of chokidar. This file is the map back to the original and the record of
every place we differ.

## Divergences

Each is tagged in code as `// DVn`. Relative to the pinned v6 commit these are the only behavioural
departures; everything else is a verbatim translation (see the function map). The IDs come from the
planning document and are kept for traceability; withdrawn IDs are listed so nobody re-adds them.

| ID   | Upstream behaviour                                                                       | chokibare                                                                                                                                                                                                                                                         | Why                                                                 | Test                                                   |
| ---- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------ |
| DV10 | `process.nextTick` schedules `ready`                                                     | `queueMicrotask`                                                                                                                                                                                                                                                  | no `process` under Bare                                             | every `ready`                                          |
| DV11 | "recursive unsupported" is learned from `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM` at runtime | Bare on Linux only: the recursive "unsupported" latch is pre-set, because libuv ignores the flag silently there and bare-fs cannot raise that error; roots take the per-directory path exactly as upstream does after the error. Node keeps upstream's behaviour. | libuv `src/unix/linux.c` never reads the flags argument             | `test/bare-facts.js` F2, the suite under Bare on Linux |
| —    | a watch path is passed through                                                           | under Bare a path over 4096 bytes is refused with `ENAMETOOLONG`                                                                                                                                                                                                  | bare-fs copies paths into a 4096-byte buffer and truncates silently | `test/bare-hardening.js` B25                           |
| —    | no such export                                                                           | `facts()` reports shared native handles and the inotify budget                                                                                                                                                                                                    | mirall's logging and tests                                          | `test/bare-hardening.js` B08                           |
| —    | `readdirp` (Node streams)                                                                | `lib/read-dir.js`, same contract                                                                                                                                                                                                                                  | bare-fs has no Node streams                                         | `test/read-dir.js`                                     |

**Withdrawn during the port** (the plan listed them; v6 already covers them or the evidence said no):

- DV2/DV16 per-file kqueue on macOS as an opt-in: deferred past v0. Measured (S5): a directory-only
  FSEvents watcher loses nothing under sustained load up to 30 k edits/s; it loses only when the
  client stalls past FSEvents' ~640-event queue, and libuv discards the rescan notice, so no
  library can know. The remedy is a periodic rescan or a native binding that surfaces
  `MustScanSubDirs`, not per-file handles.
- DV3 (skip directory re-reads on Linux `change`): v6 reconciles the named candidate and re-reads a
  directory only on null-name or directory-level triggers, so nothing to do.
- DV7 (lstat only new entries): the engine needs stats for every entry; readdirp semantics kept.
- DV12 (`followSymlinks: true` unsupported): v6's symlink cases pass under Bare; supported.
- DV14 (null filename): v6 handles `null` names; bare-fs < 4.8.2 crashed before JS saw one on
  Windows ([bare-fs#52](https://github.com/holepunchto/bare-fs/issues/52), fixed in 4.8.2 by [#53](https://github.com/holepunchto/bare-fs/pull/53); reproduction in [ok/bare-fs-watch-repros](https://github.com/ok/bare-fs-watch-repros)).
- DV15 (subtree rescan on `MustScanSubDirs`): the notice never reaches JS (S5).

Kept from v6 unchanged (listed so nobody "fixes" them): scan-time callback buffering (1024),
native-name validation, ancestor ignore checks, the Windows parent handle for a watched root, the
macOS one-shot exact-target handle, recursive-root runtime fallback, the injected Scheduler, echo
suppression windows (25 ms / 10 ms), the 50 ms change window with replay, atomic, awaitWriteFinish,
`cwd`, `depth`, `followSymlinks`, the env overrides.
